1. DATABASE / BACKEND — WHAT IT USES
------------------------------------------------------------------------
- Backend framework : NestJS
- Database          : MongoDB (via Mongoose ODM, mongoose v8)
- Also used         : Redis (cache / queues / OTP throttling), AWS S3 (files/images)
- DB connection     : server/.env -> MONGO_URI  (was a MongoDB Atlas cluster,
                      db name "ed-hippo-db")
- To use your OWN database: change MONGO_URI in server/.env to a new Atlas
  cluster or a new db name. Collections auto-create on first write.
- Recommended free stack: MongoDB Atlas (DB) + Upstash (Redis) + Render (API).
- IMPORTANT: rotate/replace all old secrets in server/.env for your project
  (Atlas password, AWS keys, Razorpay LIVE keys, Firebase key).

7. DEPLOYMENT (all free tier)
------------------------------------------------------------------------
Recommended:
  - Frontend : Vercel      (https://vercel.com)
  - Backend  : Render      (https://render.com)  [Docker web service]
  - Database : MongoDB Atlas free M0
  - Redis    : Upstash     (https://upstash.com)

Backend (Render) settings:
  - Runtime: Docker  (uses server/Dockerfile)
  - Region : Singapore (closest to Dubai + India)
  - Plan   : Free ($0)  [note: free instances sleep after inactivity, ~30-60s
             cold start on first request]
  - Env vars: MONGO_URI, REDIS_HOST/PORT/PASSWORD, JWT_SECRET, S3_*, FIREBASE_*,
             mail/Razorpay/OAuth keys (YOUR values, not EdHippo's).

Frontend (Vercel) settings:
  - Env vars: NEXT_PUBLIC_API_HOST = https://<your-render-backend>.onrender.com
             + all 7 NEXT_PUBLIC_FIREBASE_* values.
  - IMPORTANT: NEXT_PUBLIC_* vars are baked at BUILD time -> after adding them
             you MUST redeploy.

Wiring the two together:
  - Vercel: NEXT_PUBLIC_API_HOST = Render backend URL (without /api).
  - Render backend: allow the Vercel URL in CORS + OAuth callback URLs.

8. BUILD / DEPLOY ERRORS FIXED
------------------------------------------------------------------------
a) Webapp TS build error (MenuOverlay): Link href could be undefined ->
   fixed with `href={navItem.path ?? "/"}`.
b) Render Docker build: "lockfile needs update / --frozen-lockfile" ->
   root cause was server/yarn.lock out of sync with package.json. Regenerated
   yarn.lock (verified frozen-lockfile passes for both Docker steps).
c) Then EROFS + a mongoose auto-upgrade (8.0.3 -> 8.24) broke the server TS
   build (29 type errors). Fixed by pinning EXACT versions the project compiles
   with:
      package.json: "mongoose": "8.0.3"  + resolutions { "bson": "6.2.0" }
   -> mongoose 8.0.3 / mongodb 6.2.0 / bson 6.2.0 (verified in-sync).
d) Webapp runtime "fetch failed ECONNREFUSED 127.0.0.1:8080" / "Something went
   wrong": caused by the app calling localhost because NEXT_PUBLIC_API_HOST was
   not set on the host (and/or backend not live). Fix = set env + redeploy +
   backend live (see section 7). Home/layout render paths verified crash-safe
   when API is down.
